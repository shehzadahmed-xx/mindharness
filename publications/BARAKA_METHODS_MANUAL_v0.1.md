## How to use

Every clause of a Baraka transaction package must carry five pointers:

| pointer | question it answers |
|---|---|
| **Warrant** | Which classical axiom makes this clause admissible? |
| **Proposition** | Which ESC/SpringFish result predicts what the clause does? |
| **Observer** | Which choice-point or record measures whether it did that? |
| **Status** | `[OBSERVED]` / `[SIM]` / `[UNMEASURED]` |
| **Disclosure** | What the investor/board document must say about it |

**A clause with no Observer row ships as faith, not design. A clause whose Observer
has never fired ships as hypothesis. Both are permitted; neither may be described
as tested.**

## Section 6 — The transaction simulation protocol

Before signature, the package runs through the engine:

1. Freeze the transaction constitution set (≥3 variants incl. one conventional-debt
   comparator and one negative control expected to pass clean).
2. Common random numbers across all variants; ≥8 frozen seeds.
3. Preregister directional predictions (which clause moves which state, direction only).
4. Run; report equilibria, regret, loss-paths per actor; label everything SIM.
5. Attach the report to the decision memorandum with the fidelity-index placeholder
   until observed data exists.
